# WarehouseAPI

**WarehouseAPI** — RESTful Web API для управления складскими товарами и категориями. Проект разработан на платформе ASP.NET Core с использованием Entity Framework Core и PostgreSQL.

Основная цель проекта — создание серверной части системы складского учёта, которая позволяет получать, добавлять, изменять и удалять информацию о товарах и категориях, а также выполнять поиск и постраничную выдачу данных.

Проект создан в учебных целях для практического изучения backend-разработки на C#, принципов построения REST API, работы с реляционными базами данных и тестирования приложений.

## Используемые технологии

- **C#** — основной язык программирования.
- **ASP.NET Core Web API** — создание HTTP API и обработка запросов.
- **Entity Framework Core** — ORM для взаимодействия с базой данных.
- **PostgreSQL** — реляционная система управления базами данных.
- **Npgsql** — провайдер PostgreSQL для Entity Framework Core.
- **Swagger / OpenAPI** — документация и тестирование HTTP-эндпоинтов.
- **xUnit** — написание автоматизированных тестов.

## Архитектура проекта

Проект организован с разделением основных компонентов по назначению.

| Компонент | Назначение |
|---|---|
| `Controllers` | Обработка HTTP-запросов и управление ответами API. |
| `Models` | Модели данных, представляющие сущности системы. |
| `DTOs` | Объекты передачи данных между клиентом и сервером. |
| `Data` | Контекст базы данных и настройки взаимодействия с PostgreSQL. |
| `Migrations` | История изменений структуры базы данных. |

### Основные сущности

**ProductModel** — модель товара.

Содержит информацию о товаре:
- Идентификатор.
- Название.
- Цена.
- Количество на складе.
- Идентификатор категории.
- Связанная категория.

**CategoryModel** — модель категории.

Содержит:
- Идентификатор категории.
- Название категории.
- Коллекцию связанных товаров.

Связь между товарами и категориями реализована по принципу «один ко многим»: одна категория может содержать несколько товаров.

### DTO (Data Transfer Objects)

DTO используются для передачи данных между клиентом и сервером.

Они позволяют отделить внутренние модели базы данных от объектов, которые API принимает и возвращает клиенту.

В проекте используются отдельные DTO для создания, обновления и получения данных.

## Возможности API

### Работа с товарами

API предусматривает операции управления товарами:
- Получение информации о товарах.
- Создание новых товаров.
- Обновление существующих товаров.
- Удаление товаров.

### Работа с категориями

API предусматривает операции управления категориями:
- Получение списка категорий.
- Получение категории по идентификатору.
- Создание новой категории.
- Обновление категории.
- Удаление категории.
- Поиск категорий по названию.
- Постраничная выдача результатов (пагинация).

### Поиск и пагинация

Для получения категорий поддерживаются query-параметры:

| Параметр | Описание | Значение по умолчанию |
|---|---|---|
| `search` | Поиск категории по названию | Не задан |
| `page` | Номер страницы | `1` |
| `pageSize` | Количество элементов на странице | `10` |

Максимальный размер страницы — 100 элементов.

Для поиска используется `EF.Functions.ILike`, обеспечивающий поиск по тексту без учёта регистра в PostgreSQL.

Пример запроса:

`GET /api/Category?search=Electronics&page=1&pageSize=10`

Результат содержит информацию о текущей странице, размере страницы, общем количестве найденных записей, количестве страниц и список категорий.

## Работа с базой данных

В качестве основной базы данных используется PostgreSQL.

Взаимодействие с ней организовано через Entity Framework Core.

Для настройки подключения используется `WarehouseDbContext`, который определяет наборы сущностей и обеспечивает работу с таблицами базы данных.

Изменения структуры базы данных отслеживаются и применяются с помощью механизма миграций Entity Framework Core.

Основные сущности базы данных:
- `Products` — товары.
- `Categories` — категории.

## Тестирование

Для проверки корректности работы приложения используются автоматизированные тесты на базе xUnit.

Тесты разделены на две основные категории.

### Unit Tests — модульные тесты

Модульные тесты предназначены для проверки отдельных компонентов приложения независимо от остальной системы.

Они позволяют проверять корректность выполнения отдельных методов, бизнес-логики и валидации данных.

### Integration Tests — интеграционные тесты

Интеграционные тесты предназначены для проверки взаимодействия нескольких компонентов приложения.

В частности, проверяется работа HTTP-эндпоинтов, обработка запросов и формирование ответов API.

Для тестирования HTTP-запросов используется `WebApplicationFactory`, позволяющий запускать приложение в тестовом окружении и обращаться к нему через `HttpClient`.

## Запуск проекта

### 1. Требования

Перед запуском необходимо установить:

- .NET SDK, совместимый с целевой версией проекта.
- PostgreSQL.
- IDE или редактор кода, поддерживающий .NET (например, Visual Studio или JetBrains Rider).

### 2. Клонирование репозитория

```bash
git clone https://github.com/everidiy/WarehouseAPI.git
cd WarehouseAPI
```

### 3. Настройка подключения к базе данных

В файле `appsettings.json` необходимо указать строку подключения к PostgreSQL.

Пример:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=warehouse_api;Username=postgres;Password=YOUR_PASSWORD"
  }
}
```

Замените `YOUR_PASSWORD` на пароль пользователя PostgreSQL.

Не рекомендуется хранить реальные пароли и другие секретные данные в публичном репозитории.

### 4. Применение миграций

Для создания таблиц и применения миграций выполните:

```bash
dotnet ef database update
```

### 5. Запуск приложения

```bash
dotnet run
```

После запуска API будет доступно по адресу, указанному в консоли.

Документация Swagger доступна по адресу:

`https://localhost:PORT/swagger`

Вместо `PORT` необходимо указать порт, который приложение выдало при запуске.

## Запуск тестов

Для запуска всех автоматизированных тестов из корневой директории решения выполните:

```bash
dotnet test
```

Для запуска тестов конкретного проекта:

```bash
dotnet test WarehouseAPI.Tests
```
